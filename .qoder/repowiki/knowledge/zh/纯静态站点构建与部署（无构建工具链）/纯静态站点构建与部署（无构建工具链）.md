## 1. 使用的系统/方法

本项目是一个**纯静态 HTML/CSS/JS 站点**，没有任何构建工具链、包管理器或编译步骤。项目直接以源码形式部署到静态托管平台：
- **本地预览**：通过任意 HTTP 服务器直接运行，如 `python -m http.server`、`npx http-server`，或直接双击 `index.html`。
- **生产部署**：直接推送源码至 GitHub 仓库，由托管平台自动发布为静态站点。

支持的部署目标包括：GitHub Pages、Vercel、Cloudflare Pages、Netlify，以及自建 Nginx 服务器。

## 2. 关键文件

- `README.md` / `Readme-en.md`：文档中详细描述了所有部署方式（Nginx、Vercel CLI、GitHub Pages、Cloudflare Pages、Netlify），并说明“Build Command”和“Output Directory”均留空。
- `index.html`、`commit.html`、`404.html`、`about/index.html`：站点页面，即最终产物。
- `assets/`：全部前端资源（CSS、JS、图片、字体库 FontAwesome、Bootstrap 等）均为已预编译的静态文件，直接引用。
- `.gitignore`：仅忽略 `.DS_Store`，未忽略任何构建产物（因为不存在构建产物）。
- `web_tool-master.zip`：仓库附带一份压缩包形式的发布产物。

## 3. 架构与约定

- **零构建**：没有 `package.json`、`Makefile`、`Dockerfile`、`.github/workflows`、`vercel.json` 等任何构建/CI 配置文件。README 中虽提及 `vercel.json` 作为可选配置，但当前仓库根目录并不存在该文件。
- **直接分发源码**：部署流程是“源码 → 静态托管平台”，平台将根目录下的 HTML/CSS/JS/图片原样服务。
- **CDN/第三方依赖内联**：Bootstrap 4.3.1、jQuery 1.11.1/3.2.1、FontAwesome 5.15.4、Fancybox 3.5.7 等均以本地副本形式存放在 `assets/` 下，不依赖 npm/yarn 安装。
- **多页站点结构**：每个功能对应一个独立 HTML 文件（首页、提交页、关于页、404 页），通过相对路径互相链接。

## 4. 约定与约束

- **无需后端**：README 明确声明“纯静态 HTML 页面，无需后端支持”，因此不存在服务端构建、模板编译或 API 打包过程。
- **部署命令为空**：在 Vercel、Cloudflare Pages、Netlify 等平台配置时，“Build Command”和“Output Directory”均保持默认/留空，直接输出根目录。
- **Nginx 部署需手动上传**：README 提供的是 `scp -r ./* user@your-server:/var/www/web_tool/` 全量拷贝命令，而非自动化 CI 流水线。
- **版本管理即发布**：Git 分支/标签即为版本标识；仓库附带 `web_tool-master.zip` 作为一次性发布的归档产物。
- **无自动化测试/Lint/格式化**：未发现 ESLint、Prettier、Stylelint、Jest 等任何质量保障脚本。
- **无容器化**：未发现 Dockerfile 或 docker-compose 文件。
- **无 CI/CD 流水线**：仓库根目录不存在 `.github/` 工作流目录，也没有其他 CI 配置文件。

总结：本项目的“构建系统”本质上就是**零构建**——源码即产物，由静态托管平台直接提供服务。所有“构建”概念都由外部托管平台隐式完成，仓库本身不包含任何构建脚本或配置。
